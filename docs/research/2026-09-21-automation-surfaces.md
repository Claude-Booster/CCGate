# Automating Token & Context Optimization in Claude Code: A Build Guide for "ccgate"

## TL;DR

- **The four cost drivers you flagged are genuinely uninterceptable from inside interactive Claude Code.** No hook output can invoke `/compact`, `/clear`, switch models, or connect/disconnect an MCP server. `PreModelSwitch` and `PreCompact` hooks can *block* those events but cannot *initiate* or *redirect* them (there is no `updatedModel` field, and no `triggerCompact`/`action:"compact"` field on any event). Your diagnostic design is correct that PreToolUse can't reach these — the honest answer is that **interactive Claude Code caps out at "detect + advise + block," not "automatically fix."**
- **True automatic control requires owning the loop.** Rebuilding ccgate on the **Claude Agent SDK** (headless `query()` loop) gives you programmatic `/compact` and `/clear` (sent as the prompt string), `setModel()` mid-session, `canUseTool`, callback hooks, and full message-history editing. At the **raw Anthropic API** layer you additionally get server-side `context_management` (`clear_tool_uses_20250919`, `clear_thinking_20251015`, `compact_20260112`), the memory tool, and cache-aware clearing via `clear_at_least`. Anthropic's own 100-turn web-search evaluation reported an 84% token reduction from context editing.
- **Recommended architecture: a hybrid.** Keep ccgate's diagnostics and PreToolUse hooks for interactive sessions, but move the actual optimization into either (a) an Agent-SDK-owned loop for unattended/CI work, or (b) a proxy that injects `cache_control`, 1h TTL, and server-side `context_management`. A proxy is the only layer that can transparently front an *existing* interactive session, but it breaks Claude Code's native MCP tool-search deferral (a non-first-party `ANTHROPIC_BASE_URL` disables it), so it can *cost* you more context than it saves unless you set `ENABLE_TOOL_SEARCH=true`.

## Key Findings

### 1. What can and cannot be automated at each control point

**Hooks (interactive Claude Code).** The current hooks reference documents roughly 30 lifecycle events. The ones relevant to your cost drivers:

- `PreModelSwitch` — fires before a requested model switch. **Can block** via `hookSpecificOutput.permissionDecision: "deny"`, top-level `{"decision":"block","reason":...}`, or exit code 2 (a hook cancelled at its timeout also blocks). Input is `from_model`/`to_model`; the matcher is the canonical target model name (e.g. `claude-opus-5`, `.*opus.*`). **Cannot redirect** to a different model — there is no `updatedModel` or equivalent field, and PreModelSwitch is explicitly *not* in the docs' list of events that can rewrite content (only `PreToolUse.updatedInput`, `PermissionRequest.decision.updatedInput`, `PostToolUse.updatedToolOutput`, and `UserPromptSubmit.additionalContext` can rewrite/inject).
- `PostModelSwitch` — context-only. Can inject `hookSpecificOutput.additionalContext` (delivered with the next request); **cannot block** — "the model already switched."
- `PreCompact` / `PostCompact` — `PreCompact` can *block* compaction (top-level `decision:"block"`); neither can *start* one. A `PreCompact` hook's top-level `systemMessage` is discarded (PreCompact has no `additionalContext` channel), so checkpoint state to a file instead (e.g., write `HANDOFF.md`), or move the snapshot to a `SessionStart` hook that injects on `source=compact`. Claude Code v2.1.261 rejects a `hookSpecificOutput.hookEventName:"PostCompact"` variant — the schema only accepts variants for PreToolUse, PermissionRequest, UserPromptSubmit, PostToolUse, PostToolBatch, and Stop/SubagentStop.
- **No hook** — PreCompact, Stop, SessionStart, Notification, SessionEnd, PreToolUse, PostToolUse, UserPromptSubmit, SubagentStop — has any output field that can *invoke* a slash command, compaction, clear, or model switch. Anthropics/claude-code issue #58538 states verbatim: *"No hook output field triggers compaction (no triggerCompact, compact, action: \"compact\", etc. on any hook type)… No slash command, skill, MCP tool, or env var can trigger it."* Issue #37307: *"Custom slash commands and hooks have no way to programmatically trigger /clear or /compact. These are client-side CLI operations with no extension point."*

Content-rewriting hook outputs that DO exist power your existing rules: `PreToolUse.updatedInput` (Bash-output-rewriter / path-denier via `permissionDecision:"deny"`), `PostToolUse.updatedToolOutput` (rewrite results), and `UserPromptSubmit.additionalContext` (inject, cannot replace). Four handler types exist: `command`, `http`, `prompt` (LLM-in-the-loop, Haiku by default), and `agent` (spawns a subagent). Async/non-blocking hooks exist for logging/side-effects. Universal envelope fields: `continue:false` (halts, takes precedence over `decision`), `stopReason`, `suppressOutput`, `systemMessage`; string outputs (`additionalContext`, `systemMessage`, `initialUserMessage`) are capped at 10,000 characters each.

**settings.json (context/token-relevant keys).** `autoCompactEnabled` (bool, default `true` — the documented on/off switch; note it was reported *missing* from the schema in issue #38483 and has since been documented, so version-check it), `autoCompactWindow` (100K–1M token trigger; unusually, it can push the trigger *later* than the model default via the setting, `/autocompact 500k`, or `--autocompact`). Precedence: `CLAUDE_CODE_AUTO_COMPACT_WINDOW` > `--autocompact` flag > `/autocompact` > `autoCompactWindow` setting > model default. **Editing CLAUDE.md or settings.json mid-session does NOT take effect until restart and does NOT invalidate the cache. MCP config edits take effect only on restart** — which is precisely when the connect/disconnect (and its cache invalidation) happens.

**Environment variables.** `ENABLE_TOOL_SEARCH` (`true`/`false`/`auto`/`auto:N`), `MAX_THINKING_TOKENS` (0 disables thinking except on Fable models, which cannot disable thinking), `ENABLE_PROMPT_CACHING_1H` / `FORCE_PROMPT_CACHING_5M` (v2.1.108+; deprecates `ENABLE_PROMPT_CACHING_1H_BEDROCK`), `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` (v2.1.257+; accepts only `"5m"` or `"1h"`), `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` (only *lowers* the threshold; values above the model default are ignored), `DISABLE_AUTOCOMPACT`/`DISABLE_COMPACT`, `CLAUDE_CODE_MAX_CONTEXT_TOKENS` (for recognized models only takes effect when `DISABLE_COMPACT` is also set, v2.1.193+), `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` (`ANTHROPIC_SMALL_FAST_MODEL` is deprecated in favor of `ANTHROPIC_DEFAULT_HAIKU_MODEL`), and Bash/task output truncation caps.

**The Agent SDK (own-the-loop).** `query()` accepts `/compact` and `/clear` **as the prompt string** — this is the programmatic compaction/clear API for a self-owned loop (init messages expose `slash_commands` like `["/compact","/clear","/help"]`; a `/compact` result carries `compact_metadata.trigger`). Other controls: `setModel()` (change model mid-conversation), `setPermissionMode()`, the `canUseTool` callback (runtime allow/deny — how you build human-free pipelines), callback `hooks` (PreToolUse/PostToolUse/etc. as functions returning allow/block/modify/inject), `effort` (low→max) and `max_thinking_tokens`, `agents` for subagents, session `resume`/`continue`, and `listSessions`/`getSessionMessages` for transcript inspection/editing. **Anthropic recommends server-side compaction over SDK client-side compaction** ("handles context management automatically with less integration complexity, better token usage calculation, and no client-side limitations").

**The raw API.** `context_management` parameter (beta header `context-management-2025-06-27`):
- `clear_tool_uses_20250919` — params: `trigger` (default 100,000 input tokens; can be `tool_uses`), `keep` (default 3 tool uses), `clear_at_least` (default none — the anti-thrash guard), `exclude_tools` (default none), `clear_tool_inputs` (default false). Replaces cleared results with placeholder text.
- `clear_thinking_20251015` — `keep` (`{type:"thinking_turns",value:N}` or `"all"`). Must be listed first if combined. Per-model defaults: Opus 4.5+/Sonnet 4.6+ keep all; earlier Opus/Sonnet and all Haiku keep last turn only.
- Server-side compaction `compact_20260112` (beta header `compact-2026-01-12`; supported on Opus 4.6+, Sonnet 4.6+, Fable/Mythos 5): params `instructions`, `pause_after_compaction`; emits stop_reason `compaction`; reads from the existing prefix cache rather than re-tokenizing.
- Memory tool `memory_20250818` for offloading context to files.
- `count_tokens` returns `input_tokens` (after edits) vs `context_management.original_input_tokens` (before) — preview savings before spending. Response `context_management.applied_edits` reports `cleared_tool_uses`/`cleared_thinking_turns`/`cleared_input_tokens` (in the final `message_delta` for streaming).

**MCP tool search.** Default-on for first-party hosts and supported models (needs `tool_reference` blocks: Sonnet 4/Opus 4 and later). With deferral, only tool names + server instructions load at session start; **a server connecting, disconnecting, or changing its tool list only *appends* content and leaves the cached prefix intact** — this is the built-in fix for the "MCP invalidates the tool-definition prefix" problem you flagged. But `alwaysLoad:true` (per server in `.mcp.json`), threshold loading (`auto:N`), or any always-loaded tool re-exposes the invalidation by putting definitions in the prefix. **A non-first-party `ANTHROPIC_BASE_URL` disables tool search by default** (documented on the env-vars page); HTTP-transport MCP tools also weren't deferred in some versions (issue #40314 measured 120K tokens / ~60% of a Sonnet window loaded upfront through a LiteLLM gateway). Limits: up to 10,000 deferred tools per request; searches return up to 5 tools by default (Claude can raise `limit`).

### 2. Prompt-cache economics (the constraint everything orbits)

- Cache key = hash of the ordered prefix: **system prompt + tool definitions + CLAUDE.md + conversation history**, plus **two non-text keys: model and effort level**. Change anything → everything after that point recomputes. There is no per-file or per-segment caching; the match is exact.
- Up to **4 cache breakpoints** per request. Default TTL **5 minutes**, refreshed on each read; optional **1-hour** TTL (neither requires a beta header at the API). On a Claude subscription Claude Code requests the 1h TTL automatically.
- Pricing multipliers (public model): 5m write ≈ 1.25× base input, 1h write ≈ 2.0× base, cache read ≈ 0.1×. The 1h/5m write ratio is 1.6×. Cached reads are excluded from ITPM rate limits — effectively a free rate-limit multiplier.
- **Invalidating actions** (each costs one slower, more expensive turn, then re-caches): switching models, changing effort, turning on fast mode, connecting/disconnecting an MCP server *whose tools are in the prefix*, enabling/disabling a plugin that provides prefix-loaded MCP servers, denying an entire tool (bare `Bash`/`WebFetch`; scoped `Bash(rm *)` rules are safe), compacting, accumulating many images, and upgrading Claude Code. Editing CLAUDE.md mid-session does NOT (it doesn't apply until restart).
- **Idle > TTL = cold write.** On a ~200K-token Opus session, a cold re-write is on the order of $1+ per idle gap that crosses the TTL.

### 3. Claude Code's own automatic mechanisms

- **Microcompact**: automatically content-clears old tool results from the *local* message array as context grows; the "cached microcompact" variant queues a server-side `cache_edit` that does **not** break the prompt cache, and notifies the cache-break detector so the drop in cache reads doesn't false-alarm. It runs only on the main thread and explicitly treats the >60-min-idle / cold-cache moment as a good time to clear (since the prefix is being rewritten anyway). Not user-disableable (feature request #7176). This is the closest thing to a native "auto tool-result clearer."
- **Auto-compact** near the context limit (default ~95%, or `autoCompactWindow`); most non-1M configurations compact at a 200K boundary. This is the "badly-timed compaction" driver — when the system fires it, there is no clean task boundary, so it summarizes partial plans and in-flight reasoning.
- **Subagents / Task tool**: Claude Code spawns Explore/search subagents in separate processes with their own smaller context window and independent cache, leaving the parent's cache untouched — the native pattern for high-volume exploration without polluting the main context (the tool was renamed Task→Agent in v2.1.63).

### 4. Community & expert tooling (honest assessment)

- **ccusage / Claude-Code-Usage-Monitor / claude-code-usage-analyzer**: pure measurement. They read local JSONL and break down input/output/cache-create/cache-read, cost, and burn rate. Use these for your before/after A/B; they do no optimization.
- **Serena (oraios/serena)**: an LSP/symbol-level MCP — "A powerful MCP toolkit for coding, providing semantic retrieval and editing capabilities — the IDE for your agent," with `find_symbol`, `find_referencing_symbols`, `insert_after_symbol` across 30+/40+ languages via LSP (plus a paid JetBrains backend). The strongest grep-and-read replacement. The maintainers themselves note it only pays off on medium/large codebases; on small repos the tool-description overhead and Claude Code's built-in editor make it net-negative (they dropped Serena's own regex-replace tool from the claude-code context for that reason).
- **token-optimizer-mcp (ooples / birhantprkc), claude-context-optimizer (AzozzALFiras)**: MCP servers + optional hook bundles that cache/compress file reads and tool outputs to SQLite, claiming 60–98% reductions. Treat these numbers skeptically — self-reported, gross "payload avoided" framing, measuring avoided tokens rather than *net* cost after cache-write premiums. Note their own docs admit an MCP server alone "gives the model tools but no pre-execution veto" — they need the hook bundle to actually block reads.
- **Model routers**: `claude-code-router` (musistudio), `claude-jev-model-router`, and OpenAI-compatible proxies route tiers (Haiku/Sonnet/Opus) to different providers. The **subagent-model-routing pattern** (route the Explore/search subagent to Haiku, keep the main thread's model fixed) is the *cache-safe* form — it never touches the main prefix. Routing the *main* session mid-task always burns the cache. Auto-routing the main model by task type is an open feature request (#44976), and Anthropic's own cost guidance is "Sonnet handles most coding tasks well… Reserve Opus for complex architectural decisions."
- **Superpowers (obra / Jesse Vincent)**: the canonical *automatic* context-hygiene methodology. Vincent (founder/CEO of Prime Radiant, creator of Request Tracker) built the first version in October 2025; it was accepted into Anthropic's official Claude plugins marketplace on January 15, 2026. Skills trigger automatically, and every implementation/review task is dispatched to a fresh ephemeral subagent with a blank context window *specifically* to keep the orchestrator's context clean ("one of the reasons we use subagents to code review is we don't want to pollute your context window"). Simon Willison (Oct 10, 2025): "Jesse is one of the most creative users of coding agents (Claude Code in particular) that I know… It uses subagents to manage token-heavy stuff, including all the actual implementation," adding "I can't recommend this post strongly enough."

### 5. Evidence quality

Anthropic's official announcement "Managing context on the Claude Developer Platform" (Sept 29, 2025) reports, verbatim: *"In a 100-turn web search evaluation, context editing enabled agents to complete workflows that would otherwise fail due to context exhaustion—while reducing token consumption by 84%,"* and *"combining the memory tool with context editing improved performance by 39% over baseline. Context editing alone delivered a 29% improvement."* These are **Anthropic-internal evals, not independent third-party benchmarks.** Community "60–98%" claims are largely unsubstantiated gross-payload figures. The reliable methodology is a ccusage before/after on the *same replayed task*, with cache-create vs cache-read separated — because the central risk is that "savings" are cost *moved* into cache-write premiums or into more output tokens (summaries), not removed.

**Stale claim to avoid:** the recycled "MCP servers cost ~18,000 tokens per turn" traces to the pre-tool-search era (Anthropic issue #3406, "built-in tools + MCP descriptions load on first message causing 10–20k token overhead"; MindStudio measured "up to 18,000 tokens per turn"). Since MCP Tool Search shipped (Simon Willison flagged the fix Jan 14, 2026), first-party MCP tool definitions are deferred by default and cost almost nothing until invoked (one measurement showed a 46.9% cut, ~51,000→8,500 tokens). Do not cite the 18K figure as current.

## Details — Maximum achievable automation per architecture

| Cost driver | (a) Interactive CC (hooks+settings+plugins) | (b) Agent SDK (self-owned loop) | (c) Proxy in front of the API |
|---|---|---|---|
| **Model switch mid-session** | Cannot initiate/redirect. `PreModelSwitch` can only *block* an externally-requested switch (no `updatedModel`). Best available: route the *subagent* model via config (cache-safe). | Full: `setModel()` at task boundaries; keep the main model fixed and delegate to Haiku subagents. | Full: rewrite the `model` field per request and classify task (jev-style). Breaks the main-thread cache if you swap mid-conversation — route *subagent* requests only. |
| **MCP tool-set change invalidating the prefix** | Keep tools *deferred* (`ENABLE_TOOL_SEARCH`, lint out `alwaysLoad`); that makes connect/disconnect append-only and cache-safe. Cannot force a reconnect programmatically. | Same deferral applies; you control `mcpServers` and can pre-connect all servers at session start. | Proxy can hold MCP connections stable and present a fixed tool list, decoupling server churn from the prefix — but a non-first-party base URL *disables* CC's native deferral, so you must forward `tool_reference` blocks or set `ENABLE_TOOL_SEARCH=true`, else you re-load 100K+ tokens upfront. |
| **Prompt-cache TTL expiry during idle** | `ENABLE_PROMPT_CACHING_1H`; `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL=1h`. Cannot send keepalive pings. Microcompact already exploits the cold-cache moment. | Send a cheap keepalive request within the TTL window to keep the prefix warm; set `cache_control ttl:"1h"`. | Strongest control: inject `cache_control ttl:"1h"` on the stable prefix and optionally emit keepalive reads. |
| **Badly-timed compaction** | Cannot trigger `/compact`; can only *block* auto-compact (`PreCompact` deny / `autoCompactEnabled:false`) and advise. `PreCompact` hook can checkpoint state to a file. | Full: send `/compact` as a prompt string at a *chosen* boundary; or run server-side `compact_20260112` with custom `instructions` + `pause_after_compaction`. | Full: inject `context_management` (`clear_tool_uses_20250919` and/or `compact_20260112`) into the request body; the proxy decides when. |

**Genuinely impossible today (needs an Anthropic feature request):** programmatically triggering `/compact`, `/clear`, or a model switch *from inside a running interactive session* (via hook, custom slash command, skill, MCP tool, or env var). Confirmed by open issues #58538, #37307, #66246, #85289 and the closed-NOT_PLANNED #65586 ("programmatic model switch for a running session"). Redirecting a model switch to a different target via `PreModelSwitch` is also impossible (no `updatedModel` field). Remote Control can dispatch `/clear`, `/compact`, `/model` into a running session from web/mobile, but only an authenticated human can send — there is no local/programmatic entry point.

**Cache-aware mechanisms worth building on:**
- Server-side `context_management` is applied *after* cache lookup, and `clear_at_least` exists precisely so you only break the cache when you'll recover enough tokens to justify the re-write — this is your anti-thrashing lever.
- Memory tool + clearing: as context nears the clear threshold, Claude receives an automatic warning to persist findings to memory files before the clear — the built-in "externalize state so context can be cleared safely" pattern.
- `compact_20260112` reads from the existing prefix cache (system prompt + tools + history + a summarization instruction), avoiding the full re-tokenization that client-side summarization incurs.

## Recommendations

**Stage 1 — Keep diagnostics, add the safe interactive levers (ship now).** Retain ccgate's cache-hit measurement, cause attribution, and settings linter. Automatically enforce the cheap wins users forget: set `ENABLE_PROMPT_CACHING_1H` (or `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL=1h` for multi-agent runs), set `ENABLE_TOOL_SEARCH=true` whenever a non-first-party base URL is present, keep MCP tools deferred (lint for `alwaysLoad`), and pin model + effort at session start. Add a `PreModelSwitch` hook that blocks accidental mid-task switches while the cache is warm, and a `PreCompact` hook that checkpoints state to `HANDOFF.md` (remember its `systemMessage` is discarded — write to disk, and inject on next `SessionStart` with `source=compact`). **Escalation trigger:** if ccusage shows cache-read / (cache-read + cache-create) < ~0.7 across sessions, the invalidation problem is real — go to Stage 2.

**Stage 2 — Build the real optimizer on the Agent SDK for unattended/CI work.** For headless, scripted, or CI use, own the loop with `query()`. Programmatically `/compact` at task boundaries (or run server-side `compact_20260112`), delegate all high-volume exploration to fresh Haiku subagents (the Superpowers pattern), call `setModel()` only between tasks, and externalize findings to the memory tool before clearing. This is where measurable 30–80% reductions are realistic. **Threshold to keep it:** net cost (not gross tokens avoided) must fall on replayed A/B tasks.

**Stage 3 — Optional proxy for transparent interactive optimization.** If you must optimize *existing* interactive sessions without rewriting them, front the API with a proxy that (a) injects `cache_control` with 1h TTL on the stable prefix, (b) applies `context_management` clearing with `clear_at_least` tuned to avoid thrashing, and (c) routes subagent requests to cheaper models. **Kill-switch threshold:** if the proxy forces a non-first-party base URL and you cannot restore tool-search deferral, MCP-heavy sessions will load 100K+ tool-definition tokens upfront (issue #40314's 120K/session, ~$0.60/session on Opus) and the proxy becomes net-negative — verify with `/context` before committing.

**Always:** prove savings with an A/B on identical replayed tasks, reporting net cost with cache-create vs cache-read separated, never gross "tokens avoided." File the Anthropic feature request for a sanctioned in-session control-plane API (referencing #58538/#65586) — it's the only path to closing the interactive gap.

## Caveats

- **Version sensitivity.** Version floors matter for your users: `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` (v2.1.257+), the 1h-cache env flags (v2.1.108+), `PreModelSwitch`/`PostModelSwitch`/`PostCompact`/Elicitation (v2.1.76+ era), Agent tool rename (v2.1.63), tool-hook timeout raised to 10 min (v2.1.3), `CLAUDE_CODE_MAX_CONTEXT_TOKENS`+`DISABLE_COMPACT` pairing (v2.1.193+), PreModelSwitch confirmation honoring cache TTL (v2.1.238+), gateway `cache_control` marker handling (v2.1.237+). Confirm against the installed CC version; several third-party-blog settings names (e.g. `autoCompactThreshold`, `bash.deniedCommands`) do not match the official schema and should be validated against `code.claude.com/docs/en/settings-reference`.
- **Betas.** `context-management-2025-06-27` and `compact-2026-01-12` are beta headers; `compact_20260112` requires Opus 4.6+ / Sonnet 4.6+ / Fable 5. Context editing invalidates cached prefixes when it clears (which is why `clear_at_least` exists); thinking-block clearing preserves the cache only when blocks are *kept*.
- **Self-reported numbers.** The 84% / 39% / 29% figures are Anthropic-internal evals; community 60–98% claims are largely unverified. Do not present them as guaranteed outcomes.
- **Cost-moving risk.** Clearing/compaction shifts cost into cache-write premiums and can increase output tokens (summaries). Only `clear_at_least`-style guards plus honest net measurement distinguish real savings from displacement.
- **Docs-fetch limitation.** The exact `PreModelSwitch` stdin JSON example was not captured verbatim from the primary page (server errors on the anchor), though the lifecycle, decision-control, exit-code, and content-rewrite tables were verified verbatim from the official hooks reference. Treat the precise stdin field names (`from_model`/`to_model`) as high-confidence but re-verify against your installed version.
